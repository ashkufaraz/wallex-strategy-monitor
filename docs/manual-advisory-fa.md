# حالت بررسی معامله دستی و پنل جزئیات

این مرحله در سورس محلی پیاده‌سازی و آزمایش شده است. قابلیت جدید فعال نشده، تنظیمات واقعی تغییر نکرده، هیچ push یا deployment انجام نشده و هیچ سفارش یا درخواست احراز هویت‌شده‌ای ارسال نشده است.

## تفاوت دو مسیر

| مورد | مسیر تأییدشده موجود | حالت جدید |
|---|---|---|
| تنظیم فعال‌سازی | `enabled` | `manual_advisory_enabled` |
| حالت ذخیره‌شده | `VERIFIED` | `MANUAL_ADVISORY` |
| وضعیت نتیجه | `READY_FOR_MANUAL_ENTRY` | `MANUAL_REVIEW_AVAILABLE` |
| عنوان فارسی | آمادگی مسیر تأییدشده | آماده بررسی برای ورود دستی |
| timestamp منبع دفتر | الزامی | نبود آن محدودیت اعتماد است؛ دریافت محلی اخیر الزامی است |
| اعتماد REST والکس | در صورت نبود مدرک رد می‌شود | همواره `UNVERIFIED` باقی می‌ماند |
| Margin/SHORT | تطبیق instrument باید تأیید شود؛ SHORT فعلاً مسدود است | صرفاً تخمین روی دفتر عمومی؛ تطبیق تعهدی و قابلیت حساب تأیید نمی‌شوند |
| سفارش واقعی | ارسال نمی‌شود | ارسال نمی‌شود |

هیچ تبدیل خودکاری از فرصت دستی به READY تأییدشده وجود ندارد. سیگنال هنگام ایجاد به حالت خود متصل می‌شود؛ تغییر flag، سیگنال قدیمی را به مسیر دیگر منتقل نمی‌کند. تأیید دستی موجود نیز فقط READY مسیر تأییدشده را می‌پذیرد؛ برای Advisory دکمه جدید ارسال یا تأیید اجرای معامله اضافه نشده است.

پیش‌فرض `manual_advisory_enabled=false` است. برای استفاده آتی، علاوه بر این flag، تحلیل بایننس و تأیید صریح نسخه استراتژی همچنان لازم‌اند. نمونه زیر **فقط توضیح تنظیمات** است و در فایل فعال نوشته نشده است:

```json
{
  "analysis_enabled": true,
  "enabled": false,
  "manual_advisory_enabled": true,
  "approved_strategy_versions": {
    "YOUR_STRATEGY_ID": "EXACT_APPROVED_VERSION"
  },
  "min_remaining_rr": 1.5
}
```

عدد RR نمونه تصمیم کاربر است، نه پیش‌فرض جدید؛ در اجرای واقعی باید مقدار دلخواه صریحاً تعیین شود. JSON نسخه ۱ استراتژی تغییر نکرده است. برای اعلان دوم، مقدار `trade.quantity` موجود باید مشخص باشد. حجم نامشخص فقط توضیح «قابل محاسبه پس از تعیین حجم» می‌دهد و فرصت ورود صادر نمی‌کند.

## دریافت مستقل و کالیبراسیون

Adapter واقعی فقط GET رسمی `/v1/depth?symbol=...` را می‌خواند. هر دریافت موفق یک `receipt_id` تصادفی مستقل دارد؛ `sample_id` مبتنی بر محتوای دفتر همچنان حفظ می‌شود. دریافت مجدد دفتر بدون تغییر می‌تواند یک دریافت مستقل باشد، اما ادعای تازه بودن منبع نیست.

`received_at` زمان محلی دریافت است؛ نه timestamp منبع. timestamp منبع تهی و اعتماد `UNVERIFIED` باقی می‌مانند. HTTP Date استفاده نمی‌شود. در Advisory فقط دریافت اخیر با ساختار معتبر، دو سمت سازگار و قیمت‌های غیرمتقاطع پذیرفته می‌شود. تکرار یک receipt حتی همراه مرجع یا زمان دریافت دستکاری‌شده، نمونه مستقل دیگری نمی‌سازد.

کالیبراسیون Advisory، series جدا از مسیر تأییدشده دارد؛ تاریخچه تأییدشده برای اعتبار دادن به Advisory مصرف نمی‌شود. Median، MAD، صدک تاریخی، تعداد نمونه‌های پنجره و تاریخچه و فاصله زمانی نمونه‌برداری همچنان کنترل می‌شوند. کمبود کالیبراسیون مانع فرصت است. اختلاف فعلی حتی قبل از تکمیل کالیبراسیون برای اطلاع نمایش داده می‌شود، ولی «طبیعی» اعلام نمی‌شود.

اعلان دوم فقط با حداقل سه نمونه مستقل متوالی و مناسب، حجم و عمق کافی، Basis طبیعی، RR کافی و اعتبار استراتژی صادر می‌شود. قطع API، داده خراب، اختلاف نامناسب، RR نامناسب یا بررسی ناموفق اعتبار، تأییدهای متوالی را قطع می‌کند. مهلت از زمان اصلی سیگنال محاسبه می‌شود و حداکثر ۹۰۰ ثانیه است؛ refresh یا restart آن را تمدید نمی‌کند. SL، TP1، ابطال و cancellation اصلی بایننس همچنان فرصت را متوقف می‌کنند.

## قیمت و RR تخمینی

VWAP خرید از ask و فروش از bid، به‌اندازه quantity ارز پایه محاسبه می‌شود. نبود عمق کافی مانع اعلان است؛ هیچ قیمتی خارج از عمق مشاهده‌شده برون‌یابی نمی‌شود. `execution_confirmed=false` باقی می‌ماند. برای SHORT، نتیجه فقط قیمت تخمینی فروش روی دفتر عمومی است، نه تأیید قیمت ورود تعهدی.

برای RR دستی، ورود از VWAP حجم‌دار می‌آید؛ تبدیل حد ضرر و هدف‌ها با همان نسبت mid دو بازار در منطق موجود انجام می‌شود. اگر هرکدام از کارمزد یا لغزش مشخص نباشد، RR ناخالص و تخمینی نمایش داده می‌شود؛ آستانه RR حدس زده نمی‌شود. حتی با هزینه‌های تنظیم‌شده، نتیجه تضمین هزینه نهایی یا امکان اجرا نیست.

## دو اعلان مستقل

1. `binance_signal` هنگام ایجاد سیگنال در تراکنش تحلیل ثبت می‌شود؛ منتظر Gate، کالیبراسیون، timestamp یا تطبیق Margin نمی‌ماند.
2. `manual_review` فقط پس از کنترل‌های فوق ثبت می‌شود و کاربر را به بررسی قیمت، هزینه و امکان اجرا در والکس راهنمایی می‌کند. UNVERIFIED صریح است.

کلیدهای یکتا و نشانگرهای ذخیره‌شده از تکرار هر دو اعلان، حتی بعد از restart یا بازگشت وضعیت مناسب، جلوگیری می‌کنند. متن اعلان‌ها دستور معامله نیست. نمایش مرورگر طبق polling فعلی است؛ اجازه اعلان، باز بودن صفحه و تنظیمات سیستم‌عامل همچنان لازم‌اند. ثبت فوری هشدار در SQLite با تضمین نمایش فوری اعلان سیستم‌عامل یکسان نیست.

## رابط جزئیات

برای مسیر بایننس، خلاصه فارسی، دو کارت قیمت، Basis و کالیبراسیون، هدف‌ها و RR، نوار زمان با deadline ثابت و نتیجه ورود دستی نمایش داده می‌شوند. سیگنال‌های نسخه جاری از نسخه‌های دیگر جدا هستند و سوابق سیگنال در بخش بازشونده می‌آیند.

وضعیت‌های شرط و اندیکاتور متن و رنگ مستقل دارند؛ شرط بررسی‌نشده با FAIL اشتباه نمی‌شود. High/Low و مقدار مشاهده‌شده هر شرط جدا هستند. OHLCV و UTC دقیق، شناسه مرحله، رویداد و دلیل فنی در قسمت بازشونده قرار دارند. پیش‌نمایش و ارزیابی واقعی با عنوان جدا مشخص‌اند. اندیکاتور تعریف‌نشده نمایش داده نمی‌شود.

قدیمی شدن quote بایننس و دریافت والکس جدا بررسی می‌شود. داده قبلی، قیمت زنده معرفی نمی‌شود. heartbeat نامعتبر، پایش فعال معرفی نمی‌شود؛ توضیح نیاز به worker یا صفحه باز و متصل نمایش داده می‌شود. نوار زمان از deadline ذخیره‌شده ساخته می‌شود، نه زمان بازکردن پنل.

## تست‌های اجراشده

- `php tests/all.php`: هر ۲۳ مجموعه موفق؛ شامل ۳۶ assertion مستقل Advisory، تست جدید اتصال به مسیر واقعی `runCycle`، ۷۳ assertion Gate موجود، ۹ assertion Monitor موجود، ۵۰ assertion Adapter و رگرسیون استراتژی‌های قدیمی.
- پنج مجموعه Node: `notifications.js`، `trade.js`، `details.js`، `execution-gate.js` و `manual-advisory.js` موفق.
- پنج برنامه Python قبلی: `deployment.py`، `indicator-reference.py`، `candle-reference.py`، `admin-diagnostics.py` و `binance-live-reference.py` موفق.
- `python tests/manual-advisory-ui.py`: اجرای مرورگر واقعی Edge در حالت headless روی HTML/CSS/JS واقعی، با تمام HTTPها به fixture محلی هدایت‌شده؛ عرض دسکتاپ ۱۴۴۰ و موبایل ۳۹۰، بدون سرریز افقی یا خطای JavaScript. نمایش PASS/FAIL/UNAVAILABLE، مقادیر High و Low، چهار وضعیت مسدودکننده و دو فراخوانی Notification بررسی شد. هیچ درخواست mutation یا درخواست واقعی به صرافی وجود نداشت.
- persistence با فایل SQLite موقت و بازکردن مجدد اتصال: حالت، سه تأیید، deadline، جلوگیری از اعلان تکراری و انقضای پایدار موفق.
- هش سورس Engine، BinanceMarketDataProvider، App و IndicatorData نسبت به شروع مرحله قبل بدون تغییر است. داده واقعی SQLite برای این آزمایش‌ها استفاده نشد.

تست مرورگر نیازمند Python Playwright و Chromium/Edge است؛ تست سبک Node به گردش CI اضافه شد. تست مرورگر با دستور بالا جدا اجرا می‌شود و به CI الزام نصب مرورگر اضافه نشده است.

## محدودیت‌های باقی‌مانده

زمان واقعی تولید دفتر والکس، تطبیق دفتر با Margin، مجوز SHORT حساب و هزینه نهایی واقعی همچنان تأیید نشده‌اند. پس از فعال‌سازی احتمالی، Advisory باید ابتدا کالیبراسیون کافی در series مستقل خود جمع کند؛ تا آن زمان اعلان دوم ندارد. بدون حجم، RR صریح، داده و عمق معتبر نیز اعلان دوم نداریم.

نمایش Notification در تست مرورگر تا فراخوانی API مرورگر تأیید شد؛ دیده‌شدن اعلان در ویندوز، مجوز واقعی کاربر و تنظیمات اعلان سیستم در این مرحله بررسی نشد. پایش دائمی هاست، انتشار، فعال‌سازی یا تست زنده حساب بخشی از این مرحله نبودند. بسته شدن صفحه در نبود worker همچنان پایش BrowserRunner را متوقف می‌کند.
