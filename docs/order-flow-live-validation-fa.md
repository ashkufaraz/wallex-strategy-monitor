# اعتبارسنجی زنده Order Flow برای BTCUSDT

تاریخ اجرا: ۲۰۲۶-۱۱-۱۱. نتیجه فعلی: **کارکرد زنده BTCUSDT تأیید نشد**. هیچ داده تاریخی یا ساختگی به‌عنوان نمونه زنده استفاده نشده است.

## اتصال واقعی

- درخواست PHP محلی به `https://data-api.binance.vision/api/v3/time`، `aggTrades?symbol=BTCUSDT&limit=1` و `depth?symbol=BTCUSDT&limit=1000`: HTTP صفر، cURL error 28، `SSL connection timeout`. سقف اتصال یک ثانیه، سقف درخواست ۱۵۰۰ میلی‌ثانیه؛ TLS verification روشن بود، اما handshake کامل و معتبر تأیید نشد. timeout به‌تنهایی نشانه نامعتبر بودن گواهی نیست.
- درخواست مستقل Python محلی، با اتصال مستقیم و TLS معتبر، به time: HTTP 451 با پیام محدودیت منطقه‌ای. این نتیجه، وضعیت مسیر خروجی PHP یا هاست را اثبات نمی‌کند.
- GET خواندنی صفحه اصلی هاست و `admin-diagnostics.php?ping=1`: هر دو ReadTimeout. از این نتیجه نمی‌توان اتصال خروجی هاست به بایننس را استنتاج کرد.
- ابزار تشخیص موجود در سورس فقط سه GET ثابت والکس دارد. بدون مسیر اجرای از قبل موجود روی هاست و با ممنوعیت Deployment، آزمایش Binance از خود هاست انجام نشده است. وجود SSH یا ابزار Binance نصب‌شده باید مشخص شود؛ هیچ فایل تشخیصی روی هاست آپلود نشده است.

## خروجی پنجره‌ها

پنجره‌های بسته UTC یک و پنج دقیقه به‌صورت مستقل در `windows` گزارش JSON ذخیره شدند. در اجرای فعلی هر دو `UNAVAILABLE` و `metrics=null` هستند؛ شمار معاملات صفر است. Delta، CVD، Imbalance و Relative Volume واقعی قابل ارائه نیستند. ترتیب شناسه‌های واقعی، تطبیق حجم واقعی، کامل‌بودن بازه و وضعیت مصرف وزن بایننس نیز بدون پاسخ موفق قابل تأیید نیستند.

ابزار جدید `tools/order-flow-live-diagnostics.php` از همان Adapter و محاسبات واقعی استفاده می‌کند، اما با SQLite حافظه‌ای و سیاست آزمایش محلی. فعال‌کردن سیاست فقط در حافظه همین فرایند است؛ فایل تنظیمات فعال نمی‌شود. داده خام عمومی، زمان دریافت، HTTP، cURL، TLS، وزن مصرفی و مراحل پردازش را ثبت می‌کند. پس از شکست مرحله اصلی، probe مستقل aggTrades و depth فقط برای تشخیص اتصال انجام می‌شود و داده ناقص آن وارد محاسبات موفق نمی‌شود.

در صورت اتصال موفق، ترتیب شناسه‌ها، pagination، تطبیق مجموع حجم معاملات با کندل بسته و پوشش باند متقارن دفتر با همان منطق تولید بررسی می‌شود. CVD در ابتدای هر پنجره صفر می‌شود؛ Relative Volume نسبت به ده پنجره پیشین هم‌طول محاسبه می‌شود. دفتر REST زمان رویداد منبع ندارد؛ زمان دریافت جدا ثبت می‌شود و به‌عنوان زمان تولید دفتر معرفی نمی‌شود. نتیجه دفتر مربوط به زمان دریافت است، نه دفتر تاریخی ابتدای پنجره.

اجرا از ترمینال موجود در محیط مورد آزمایش:

```text
php tools/order-flow-live-diagnostics.php /path/outside-public/order-flow-evidence-new.json
```

این دستور برای checkout موجود طراحی شده و خودکار روی هاست نصب نمی‌شود. مسیر خروجی باید تازه و خارج از public باشد. ابزار شواهد قبلی را بازنویسی نمی‌کند. خروجی موفق کد صفر و نتیجه ناقص کد ۲ دارد. سیاست پردازش ۴۵ ثانیه بودجه، حداکثر یک GET در هر گام و محدودیت وزن دارد؛ مشاهده 429/418 درخواست‌های بعدی تشخیص را متوقف می‌کند. این اجرا همچنان مشمول محدودیت تعداد صفحات و وزن است؛ کامل‌بودن پنج دقیقه در نماد پرتراکنش تضمین نشده است.

## جداسازی و کارایی

هیچ state، هشدار تاریخی، صف واقعی، Strategy Engine یا ExecutionGate تغییر نکرد. نتیجه آزمایش `LIVE_DIAGNOSTIC` است و در جدول سیگنال‌های برنامه ثبت نمی‌شود. فایل تنظیمات Order Flow همچنان غیرفعال است. هیچ سفارش، Push یا Deployment انجام نشد.

اجرای نخست محلی: ۳ درخواست ناموفق در حدود ۳۰۷۰ میلی‌ثانیه، CPU حدود ۶۸۸ میلی‌ثانیه و peak تخصیص PHP برابر ۲ MiB. ده هزار فراخوانی مسیر خاموش در حافظه حدود ۱٫۹۷ میلی‌ثانیه طول کشید و هیچ درخواست شبکه‌ای نداشت. اندازه‌ها مربوط به همان نمونه محلی هستند؛ مصرف موفق شبکه، بار هاست و تأخیر حلقه اصلی روی هاست اندازه‌گیری نشده‌اند. شکست زودهنگام API اجازه اندازه‌گیری هزینه پردازش حجم واقعی BTC را نداد.

## تست‌های اجراشده

- `php tests/order-flow.php`: ۴۶ assertion پاس.
- `php tests/order-flow-jobs.php`: ۱۹ assertion پاس؛ گم‌شدن/تکرار شناسه، سقف صفحه، تأخیر، backoff و جداسازی وضعیت اصلی.
- `php tests/order-flow-integration.php`: پاس؛ اعلان اصلی پیش از HTTP کمکی و حفظ وضعیت اصلی هنگام قطع API.
- `node tests/order-flow.js`: پاس؛ چهار حالت، جداسازی تاریخی/جدید و پنهان‌کردن نتیجه قدیمی یا ناقص.
- `python tests/order-flow-ui.py`: پاس؛ بررسی رابط واقعی مرورگر در دسکتاپ/موبایل با fixture، جداسازی تاریخچه، stale masking و صفر درخواست سفارش/صرافی. این تست اثبات اتصال زنده نیست.
- `python tests/order-flow-live-diagnostics.py`: پاس؛ اعتبارسنجی شواهد ذخیره‌شده، پنجره UTC، TLS روشن، نبود داده جعلی و بودجه درخواست. این تست اتصال موفق را شبیه‌سازی یا ادعا نمی‌کند.
- `php -l tools/order-flow-live-diagnostics.php`: پاس.

در تلاش اول، نام فایل تست JavaScript اشتباه وارد شد و اجرا نشد؛ سپس مسیر صحیح `tests/order-flow.js` اجرا شد و پاس کرد.

فایل‌های افزوده این مرحله: ابزار CLI، تست اعتبارسنجی شواهد، همین گزارش و گزارش JSON خلاصه کنار آن. شواهد خام اجرا زیر `data/order-flow-live-btc-diagnostic*.json`، `data/order-flow-direct-probe.json` و `data/order-flow-host-reachability.json` قرار دارند. تأیید نهایی نیازمند اجرای خواندنی موفق از خود هاست و ثبت نمونه کامل هر دو پنجره است.
