# اصلاح اعلان موبایل و پیوستگی تاریخچهٔ اندیکاتور

اعلان دسکتاپ از سازندهٔ `Notification` استفاده می‌کند. اگر مرورگر موبایل این سازنده را نپذیرد، مسیر جایگزین با `ServiceWorkerRegistration.showNotification()` فعال می‌شود. مکان‌نمای اعلان فقط پس از تحویل موفق جلو می‌رود و اجرای هم‌زمان refresh اعلان تکراری ایجاد نمی‌کند. این تغییر Push از سرور راه‌اندازی نمی‌کند؛ پایش مرورگری همچنان به صفحهٔ باز وابسته است.

در استراتژی `btc-short-breakdown-retest-01` دو مسیر جایگزین تعریف شده است: ادامهٔ مستقیم پس از بسته‌شدن ۱۵دقیقه‌ای زیر ۶۶۳۰۰، یا ریتست و سپس رد قیمت. شرط‌های مسیر دوم پیش‌نیاز مسیر اول نیستند. هشدارهای جدید، مرحله، شمارهٔ قانون و تصویر شرط‌های مسیر طی‌شده در زمان صدور را ذخیره می‌کنند. وضعیت فعلی در پنجرهٔ جزئیات ممکن است بعداً تغییر کرده باشد. هشدارهای قدیمی تصویر رویداد ندارند و تصویر تاریخی برای آن‌ها ساخته نمی‌شود.

برای BTCUSDT در بازهٔ ۲۰۲۶/۱۱/۱۲ ساعت ۰۱:۰۰ تا ۰۲:۰۰ UTC، پاسخ زندهٔ UDF والکس برای حجم ساعتی صفر بود و دادهٔ دقیقه‌ای همان ساعت نیز بدون معامله بود. این شکاف واقعی معاملات است؛ حذف یک‌بارهٔ شرط کنترل داده یا نسبت‌دادن حجم ساختگی راه‌حل درستی نیست.

فقط در سری زمانی اندیکاتورها، بازهٔ کامل بدون معامله با آخرین close یک معاملهٔ واقعی قبلی به‌صورت تخت حفظ می‌شود؛ حجم صفر می‌ماند و برچسب `continuity=last_traded_close` ذخیره می‌شود. اگر اولین بازه خالی باشد، حداکثر ۲۴ کندل پایهٔ قبلی برای یافتن قیمت معامله‌شده بررسی می‌شود. اگر قیمت معتبر قبلی یا timestamp کامل وجود نداشته باشد، نتیجه همچنان UNAVAILABLE است. تعداد بازه‌های حفظ‌شده در جزئیات اندیکاتور نمایش داده می‌شود. دادهٔ native بایننس و تجمیع کندل شرط‌های ورود تغییر نمی‌کنند.

آزمون‌های PHP، مسیرهای جایگزین، دادهٔ بدون معامله، snapshot منابع، اعلان موبایل با Service Worker واقعی، تکرار و تلاش مجدد اعلان، رابط دسکتاپ/موبایل و بستهٔ انتشار اجرا شده‌اند.
