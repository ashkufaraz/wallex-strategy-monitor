# پایش استراتژی والکس

فیلتر اختیاری RSI، EMA، ATR و حجم کندل: [راهنمای JSON و محاسبات](docs/live-indicators.md) · [نمونهٔ کامل](example-btc-short-indicators.json). استراتژی‌های قدیمی بدون تغییر کار می‌کنند؛ اندیکاتورها فقط در صورت تعریف و فعال‌سازی در JSON و هنگام تأیید نهایی ورود بررسی می‌شوند.

[Online panel](https://ashkufaraz.ir/)



برنامه‌ای با پنل فارسی برای اجرای هم‌زمان چند استراتژی مرحله‌ای روی بازارهای تتری والکس. استراتژی را به‌شکل JSON وارد می‌کنید؛ پردازشگر داده‌های عمومی بازار را بررسی می‌کند و هنگام تأیید ورود یا لغو سناریو، هشدار ثبت می‌کند.

این نسخه برای **پایش و هشدار** است. سفارش واقعی ثبت نمی‌کند و به کلید خصوصی صرافی نیاز ندارد. جزئیات سفارش در پنل برای اقدام دستی نمایش داده می‌شود.

## پیش‌نیازها

- PHP نسخهٔ **8.2 یا بالاتر** با افزونه‌های `curl`، `pdo_sqlite` و `session`.
- امکان نوشتن در پوشهٔ `data` و دسترسی شبکه به `api.wallex.ir`.
- مرورگر دارای پشتیبانی اعلان، مانند Chrome یا Edge، برای دریافت اعلان سیستم.
- Node.js فقط برای اجرای تست‌های JavaScript؛ اجرای برنامه به آن نیاز ندارد.

Composer، MySQL و Apache برای روش اجرای زیر لازم نیستند. اگر XAMPP دارید، می‌توانید از PHP همان بسته استفاده کنید. برنامه از SQLite استفاده می‌کند؛ پورت MySQL روی آن اثری ندارد.

## نصب و اجرا روی ویندوز

### ۱. بررسی PHP

پوشهٔ پروژه را باز کنید و در ترمینال اجرا کنید:

```powershell
php -v
php --ini
php check.php
```

اگر دستور `php` پیدا نشد، پوشهٔ PHP را به `PATH` اضافه کنید یا مسیر کامل آن را بنویسید. برای نمونه، در نصب XAMPP روی درایو D:

```powershell
& 'D:\xampp\php\php.exe' check.php
```

اگر بررسی افزونه‌ای را نام برد، آن را در `php.ini` مربوط به PHP خط فرمان فعال کنید و بررسی را دوباره اجرا کنید. PHP وب‌سرور و خط فرمان ممکن است تنظیمات جدا داشته باشند.

### ۲. اجرای سریع

پس از اضافه‌کردن PHP به PATH، روی فایل زیر دوبار کلیک کنید:

```text
start-windows.bat
```

این فایل پردازشگر و سرور پنل را در دو پنجره اجرا می‌کند و مرورگر را باز می‌کند. هر دو پنجره باید باز بمانند. اگر صفحه زودتر از سرور باز شد، آن را تازه کنید.

آدرس پنل: **http://127.0.0.1:5078/**

### ۳. اجرای دستی

در دو ترمینال جدا، از پوشهٔ پروژه اجرا کنید:

```powershell
# ترمینال اول: پردازشگر
php worker.php
```

```powershell
# ترمینال دوم: سرور پنل
php -S 127.0.0.1:5078 -t public
```

برای توقف هر پردازش، در ترمینال مربوط `Ctrl+C` بزنید. قفل پردازشگر از اجرای هم‌زمان دو worker روی یک پوشه جلوگیری می‌کند.

این روش با Apache روی پورت دیگری، مثلاً ۸۱، تداخلی ندارد. نسخهٔ فعلی API فقط نام‌های میزبان `127.0.0.1:5078` و `localhost:5078` را می‌پذیرد؛ تغییر صرف پورت یا بازکردن فایل از مسیر Apache کافی نیست.

## اولین استفاده

1. پنل را باز کنید و وضعیت پردازشگر را ببینید.
2. «فعال‌سازی اعلان مرورگر» را بزنید و اجازهٔ اعلان بدهید؛ سپس «آزمایش اعلان» را امتحان کنید.
3. «بارگذاری نمونه» را بزنید یا فایل JSON خودتان را انتخاب کنید.
4. پیش‌نمایش را بررسی و استراتژی را ذخیره کنید. اعتبارسنجی کامل هنگام ذخیره انجام می‌شود و وجود بازار از والکس بررسی می‌شود.
5. فاصلهٔ بررسی را در تنظیمات تعیین کنید.
6. برای دیدن روند اجرا، «جزئیات بررسی» همان استراتژی را باز کنید.

قیمت‌ها و مقدارهای نمونه، دادهٔ آموزشی‌اند؛ آن‌ها را مطابق سناریوی خود تغییر دهید. ذخیره یا شروع مجدد، پایش را از زمان فعلی آغاز می‌کند.

## خواندن صفحهٔ جزئیات

نمای اصلی برای خواندن سریع سه بخش دارد:

1. **قیمت بازار:** آخرین قیمت دریافت‌شده، زمان دریافت و وضعیت تازگی داده. این قیمت به‌صورت پیوسته یا WebSocket دریافت نمی‌شود.
2. **سفارش موردنظر:** قیمت ورود با رنگ آبی، حد ضرر قرمز و هدف‌های سود سبز؛ همراه نوع معامله، مقدار و اهرم در صورت وجود.
3. **شرط‌های ورود:** ستون سبز برای بندهای برقرار، قرمز برای برقرارنشده و زرد برای بررسی‌نشده یا دادهٔ ناموجود. مقدار مشاهده‌شده و مقدار مقایسه کنار هر بند قرار دارد.

برای شرط‌های مرکب، رابطهٔ بندها و نتیجهٔ **کل قانون** نیز نمایش داده می‌شود. سبز بودن یک بند به‌تنهایی تأیید ورود نیست. شرط‌های مراحل قبلی با زمان آخرین ارزیابی خود نمایش داده می‌شوند؛ الزاماً وضعیت قیمت فعلی را توصیف نمی‌کنند.

پیش‌نمایش شرط‌های مرحلهٔ فعلی روی آخرین کندل بسته‌شده انجام می‌شود و از شرط‌هایی که موتور واقعاً بررسی کرده جداست. انتقال کندلی تا رویداد بسته‌شدن جدید منتظر می‌ماند. گزارش‌های فنی و محاسبات سود و زیان در قسمت‌های بازشوندهٔ پایین صفحه هستند.

برای هر استراتژی حداکثر **۳۰ گزارش اخیر** و برای هر گزارش حداکثر ۱۰۰ بررسی شرط اصلی ثبت می‌شود. نسخهٔ استراتژی و جزئیات معاملهٔ زمان بررسی حفظ می‌شوند. استراتژی غیرفعال یا لغوشده گزارش تازه تولید نمی‌کند.

محاسبات سود و زیان بر اساس اختلاف قیمت و مقدار کل هستند؛ کارمزد، لغزش، اهرم و تقسیم خروج میان هدف‌ها در آن‌ها لحاظ نمی‌شود.

## قالب استراتژی

قرارداد ورودی در [راهنمای JSON](strategy-json-guide-fa.md) تعریف شده است. نسخهٔ فعلی `strategy_version: 1` است و JSON به‌عنوان داده تفسیر می‌شود؛ کد JavaScript یا PHP ورودی اجرا نمی‌شود.

| فیلد | کاربرد |
| --- | --- |
| `id`، `name`، `symbol` | شناسه، نام و بازار تتری مانند BTCUSDT |
| `enabled`، `action` | وضعیت اجرا و جهت LONG یا SHORT |
| `initial_stage`، `stages` | مرحلهٔ آغاز و قوانین انتقال |
| `max_setup_seconds` | اعتبار زمانی ستاپ پس از خروج از مرحلهٔ آغاز |
| `invalidation` | ابطال ستاپ جاری و جلوگیری از شروع آن در همان چرخه |
| `cancellation` | قوانین اختیاری لغو کامل استراتژی |
| `trade` | جزئیات اختیاری سفارش برای نمایش هنگام هشدار |

مثال زیر **فقط بخش trade** یک استراتژی SHORT است؛ برای فایل کامل از نمونهٔ همراه پروژه استفاده کنید:

```json
{
  "trade": {
    "entry": { "type": "LIMIT", "price": 75000 },
    "stop_loss": 75450,
    "take_profits": [74500, 74000],
    "quantity": 0.001,
    "leverage": 1,
    "notes": "نمونهٔ آموزشی؛ سطوح را مطابق سناریوی خود تعیین کنید."
  }
}
```

در ورود MARKET، مقدار entry برابر `{"type":"MARKET"}` است و price ندارد. قیمت مشاهده‌شده هنگام هشدار به‌عنوان مرجع ذخیره می‌شود؛ قیمت اجرای سفارش تضمین نمی‌شود. `quantity` مقدار ارز پایه است؛ مثلاً BTC در BTCUSDT. `leverage` فقط اطلاعات نمایشی است و پشتیبانی بازار یا صرافی را تأیید نمی‌کند.

## تفاوت ابطال و لغو

| رفتار | نتیجه |
| --- | --- |
| `invalidation` | ستاپ فعلی پاک می‌شود؛ بعد از رفع شرط، امکان تشکیل ستاپ تازه وجود دارد. |
| `cancellation` | کل استراتژی متوقف و دلیل لغو ثبت می‌شود؛ رفع شرط باعث ادامهٔ خودکار نمی‌شود. |
| توقف دستی | بررسی استراتژی متوقف می‌شود تا دوباره آن را فعال کنید. |

برای ادامهٔ استراتژی لغوشده، «شروع مجدد پس از لغو» را بزنید یا JSON را ویرایش و ذخیره کنید. اگر شرط لغو هنوز برقرار باشد، دوباره لغو می‌شود. لغو با راه‌اندازی مجدد worker یا حذف سوابق رفع نمی‌شود. لغو پایش، سفارش یا معاملهٔ واقعی صرافی را نمی‌بندد.

## زمان‌بندی و دادهٔ بازار

- کندل‌های `15m`، `1h` و `4h` از داده‌های یک‌دقیقه‌ای کامل ساخته می‌شوند. نبود یک دقیقه، آن کندل را نامعتبر می‌کند.
- مرز کندل‌ها UTC است؛ برای 4h، بازه‌ها از 00:00، 04:00، 08:00 و به همین ترتیب آغاز می‌شوند. منطقهٔ زمانی مرورگر مرز آن‌ها را تغییر نمی‌دهد.
- در بسته‌شدن هم‌زمان، ترتیب پردازش `4h` سپس `1h` سپس `15m` است. هر رویداد حداکثر یک انتقال دارد.
- فقط تایم‌فریم‌های استفاده‌شده در مراحل یا قوانین لغو پردازش می‌شوند. `offset` از ۱ تا ۱۰۰ است؛ کندل باز در شروط استفاده نمی‌شود.
- راه‌اندازی مجدد worker، بازیابی پس از خطا یا فاصلهٔ بیش از بزرگ‌ترِ ۱۸۰ ثانیه و سه برابر فاصلهٔ تنظیم‌شده، ستاپ‌های اجراشونده را از زمان فعلی آغاز می‌کند. سوابق حفظ و استراتژی‌های لغوشده متوقف می‌مانند.
- رویدادهای زمان خاموشی بازپخش نمی‌شوند. زمان درخواست‌های شبکه به فاصلهٔ چرخه‌ها اضافه می‌شود؛ نوسان بین دو بررسی ممکن است دیده نشود.
- قیمت بازار از آخرین معاملهٔ گزارش‌شدهٔ صرافی گرفته می‌شود؛ در بازار کم‌معامله، خود معامله ممکن است قدیمی باشد.

## اعلان‌ها و سوابق

برای اعلان سیستم، مرورگر و پنل باید باز و اجازهٔ اعلان فعال باشند. بررسی و ثبت هشدار توسط worker مستقل از بازبودن پنل انجام می‌شود.

روی آدرس loopback مانند `http://127.0.0.1:5078` مرورگرهای پشتیبان می‌توانند اعلان بدهند. برای آدرس شبکه، الزامات محیط امن مرورگر را در نظر بگیرید. اگر اجازهٔ سایت مسدود است، از تنظیمات سایت کنار نوار آدرس آن را اصلاح کنید. تنظیمات Notifications ویندوز و Focus Assist / مزاحم نشوید نیز روی نمایش اثر دارند.

پنل ۱۰۰ هشدار آخر را نمایش می‌دهد. هشدارهای قبلی هنگام بازکردن مجدد صفحه دوباره اعلان نمی‌شوند. اگر بین دو دریافت پنل بیش از ۱۰۰ هشدار ثبت شود، نمایش اعلان برای تمام آن‌ها تضمین نمی‌شود.

«حذف هشدار» یک مورد را حذف می‌کند؛ «حذف همهٔ سوابق هشدار» پس از تأیید، موارد موجود تا زمان انتخاب را پاک می‌کند، حتی موارد قدیمی‌تر از ۱۰۰ مورد قابل نمایش. هشدارهای جدیدتر حفظ می‌شوند. این عملیات برگشت‌پذیر نیست و وضعیت استراتژی‌ها را تغییر نمی‌دهد.


تست‌های PHP از SQLite مستقل در حافظه و پاسخ‌های ساختگی بازار استفاده می‌کنند؛ به اینترنت یا حساب صرافی نیاز ندارند و دیتابیس اصلی را تغییر نمی‌دهند. تست‌های JavaScript رفتار و خروجی کد رابط را بررسی می‌کنند؛ تحویل واقعی اعلان ویندوز را تأیید نمی‌کنند.

## داده‌ها، پشتیبان‌گیری و اجرای همیشگی

برای انتشار خودکار پس از push به main، [راهنمای FTPS و GitHub Actions](deploy/README-fa.md) را ببینید. workflow پیش از ارسال، تست‌ها را اجرا می‌کند و تا فعال‌کردن `FTP_DEPLOY_ENABLED` انتشار انجام نمی‌دهد. هاست رایگان InfinityFree پردازشگر دائمی این پروژه را اجرا نمی‌کند؛ بارگذاری پنل به‌تنهایی پایش ۲۴ساعته ایجاد نمی‌کند.

فایل `data/app.sqlite` اطلاعات برنامه را نگه می‌دارد. برای پشتیبان‌گیری ساده، ابتدا worker و سرور PHP را متوقف کنید و سپس کل پوشهٔ data را کپی کنید. دیتابیس، فایل‌های WAL/SHM، قفل و لاگ‌های محلی در `.gitignore` قرار دارند و نباید همراه کد در GitHub بارگذاری شوند.

خاموشی، Sleep و Hibernate پایش را متوقف می‌کنند. برای اجرای خودکار در ویندوز می‌توانید از Task Scheduler استفاده کنید و اجرای هم‌زمان چند نمونه را غیرفعال نگه دارید.

روی Linux، PHP و افزونه‌های لازم به‌همراه یک مدیر پردازش مانند systemd برای worker قابل استفاده‌اند. نسخهٔ فعلی پنل ورود کاربر ندارد و برای دسترسی محلی طراحی شده است. برای دسترسی راه دورِ همین نسخه، پنل را از طریق تونل SSH با آدرس محلی باز کنید. انتشار عمومی نیاز به افزودن احراز هویت، HTTPS و تنظیم وب‌سرور دارد. ریشهٔ وب فقط `public` است؛ ریشهٔ پروژه و data را وب‌دسترس نکنید.

## محدودهٔ نسخهٔ فعلی

اندیکاتورها و فرمول‌های دلخواه، اجرای کد استراتژی، بازپخش معاملات گذشته، ثبت خودکار سفارش، مدیریت معاملهٔ باز و تقسیم خودکار خروج میان هدف‌ها پیاده‌سازی نشده‌اند. فیلد ناشناخته به‌جای تفسیر تقریبی رد می‌شود. جزئیات امکانات ورودی را از راهنمای JSON بخوانید.

## دادهٔ صرافی و فونت

کد بازار از مسیرهای `GET /v1/markets` و `GET /v1/udf/history` با `resolution=1` استفاده می‌کند. مرجع بیرونی API: [مستندات والکس](https://api-docs.wallex.ir/). تغییر قرارداد API یا محدودیت شبکه ممکن است نیازمند اصلاح کلاینت باشد.

فونت [وزیرمتن](https://github.com/rastikerdar/vazirmatn) به‌صورت محلی در برنامه قرار دارد؛ متن مجوز آن در [public/fonts/OFL.txt](public/fonts/OFL.txt) حفظ شده است.
