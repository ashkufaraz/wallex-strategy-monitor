# گزارش صحت اسکنر

این پوشه آزمون صحت نرم‌افزار با دادهٔ مصنوعی قطعی است؛ نتیجهٔ سودآوری بازار، کارمزد واقعی حساب یا امکان اجرای واقعی شورت را اثبات نمی‌کند. هیچ استراتژی تازه‌ای اضافه نشده است. قواعد همان شکست و بازآزمایی هستند و شمارهٔ اصلاحات قواعد 1.1.0 است.

- `scanner-audit-before.md` و JSON هم‌نام: اجرای ۴۹ آزمون اولیه روی کد پایهٔ `13c2384` پیش از اصلاح؛ ۳۶ PASS و ۱۳ FAIL. این فایل‌ها شاهد اولیه‌اند و با اجرای مجدد بازنویسی نمی‌شوند.
- `scanner-audit-after.md` و JSON هم‌نام: مجموعهٔ کامل پس از اصلاح. برای تک‌تک آزمون‌ها ورودی/تغییر نسبت به fixture پایه، انتظار، خروجی واقعی و PASS/FAIL ثبت شده است.
- fixture پایه با قیمت‌های نزدیک ۱۰۰ صرفاً مصنوعی است: `tests/scanner-fixture.php`. ساعت ثابت T برابر `2024-10-04T00:00:00Z` است. مقادیر قیمت‌، حجم‌ و تنظیمات کامل در همان فایل و config گزارش آمده‌اند. سناریوها دلتاهای صریح روی این ورودی‌اند و عدد تصادفی ندارند.

اجرای مستقل از شبکه، از ریشهٔ مخزن:

```powershell
$env:PHP_BINARY='D:/xampp/php/php.exe'
python tools/scanner-audit.py
```

در Linux یا زمانی که php در PATH است، فقط دستور Python لازم است. کد خروج صفر یعنی تمام آزمون‌ها PASS هستند. گزارش JSON برای بررسی ماشینی و Markdown برای خواندن است. اجرا، SQLite موقت مستقل می‌سازد و به دیتابیس برنامه یا هاست دست نمی‌زند. هر دو گزارش after با اجرای مجدد، خروجی یکسان می‌دهند.

توابع شبکهٔ PHP (`curl_init`, `fsockopen`, `pfsockopen`, `stream_socket_client`) غیرفعال‌اند. آداپتور ساختگی فقط مسیرهای عمومی خواندن را می‌پذیرد و هر مسیر دیگر خطا می‌دهد. آزمون ثبت سیگنال، هشدار و راه‌اندازی مجدد با شش پردازهٔ واقعی PHP و مانع مشترک انجام می‌شود؛ همه یک وضعیت قبلی SQLite را می‌خوانند و فقط یک نوشتن پذیرفته می‌شود. این آزمون «توالی شبیه هم‌زمانی» نیست.

دفتر VERIFIED در دادهٔ مصنوعی، صرفاً ورودی کنترل‌شدهٔ آزمایش قرارداد است؛ آداپتور واقعی REST حتی با زمان دریافت تازه، در آزمون جداگانه UNVERIFIED می‌ماند و ورود UNAVAILABLE است. ساعت آیندهٔ حتی یک ثانیه، زمان کهنه و زمان ناموجود رد می‌شوند. هیچ حد تازگی برای عبور آزمون‌ها افزایش نیافته است.

موارد رفتاری اصلاح‌شده: تأثیر ATR ساعت نامجاز بر تلورانس سطح؛ خطای ممیز شناور در مرز تیک هدف؛ پذیرش یک ثانیه زمان آینده؛ پذیرش هزینهٔ تأمین مالی نامعلوم؛ زنده‌شدن مجدد ورود پس از ابطال؛ و مصرف مشاهدهٔ خارج از ترتیب در اجرای مرحله‌ای. موارد تکمیل اطلاعات: reason_code دقیق، نمایش بودجهٔ ریسک ۰٫۷۰، سیاست صریح اهداف، نسخهٔ قواعد و کپی کامل تنظیمات در فرصت و هشدار.

آزمون تکمیلی بازیابی، دو اصلاح دیگر را تأیید می‌کند: موجودبودن هر کندل در زمان مشاهده با available_candles ذخیره می‌شود تا دادهٔ بعداً بازیابی‌شده به گذشته راه نیابد، و خطاهای دریافت نیز به‌عنوان مشاهدهٔ data_error قابل بازپخش‌اند. مشاهدات تکراری پس از restart دوباره ذخیره نمی‌شوند. یک آزمون شورت مصنوعی هم حداقل ارزش سفارش را با VWAP واقعی عمق تطبیق می‌دهد. برابری تصمیم‌های ذخیره‌شده پس از عبور از JSON/SQLite با JSON کانونی مقایسه می‌شود؛ عدد 100 و 100.0 پس از سریال‌سازی یک مقدارند.

سیاست V1 حفظ شده است: TP1 خروج ۱۰۰٪، TP2 خروج ۰٪ و اطلاعاتی، پس از TP1 موقعیت کاملاً بسته است. تنظیم سهم خروج ۵۰/۵۰ رد می‌شود؛ پشتیبانی نمایشی یا ناقص برای خروج پله‌ای اضافه نشده است. ترتیب نامعلوم توقف/هدف، توقف اول محسوب می‌شود؛ لمس هدف در بخش نامعلوم کندل ورود، برد محسوب نمی‌شود.

در ورود داده، ترتیب نامنظم فهرست کندل‌ها با timestamp به شکل قطعی مرتب می‌شود؛ کندل تکراری متناقض، شکاف، بازهٔ بدون معامله و پنجرهٔ کهنه رد می‌شوند. ترتیب زمانی خود مشاهدات باید صعودی باشد؛ مشاهدهٔ قدیمی وضعیت را تغییر نمی‌دهد و بازپخش نامرتب صریحاً خطا می‌دهد.

در آزمون تک‌شرط، فقط همان شرط نقض می‌شود و فهرست failed_conditions و reason_code دقیق مقایسه می‌شوند. تلورانس قیمت‌های اعشاری 1e-8 نسبی است؛ شمارش، timestamp صحیح و طول لیست‌ها دقیق مقایسه می‌شوند. «عدم سفارش واقعی» برای مسیر معمول، ثبت فرصت، خطا، تکرار، اجرای هم‌زمان و تغییر تنظیمات بررسی می‌شود؛ هیچ API خصوصی سفارش فراخوانی نمی‌شود.
