# انتشار خودکار روی هاست FTP

## وضعیت فعلی پنل آنلاین

[پنل عمومی](https://ashkufaraz.ir/) بدون نام کاربری و رمز عبور باز می‌شود. همهٔ بازدیدکنندگان به داده‌های مشترک و امکان ویرایش و حذف دسترسی دارند. گردش کار با `PUBLIC_ACCESS=true` بسته می‌سازد؛ رمز پنل در این حالت لازم نیست.

بررسی استراتژی‌ها با درخواست‌های کوتاه از صفحهٔ باز انجام می‌شود. هر درخواست یک استراتژیِ موعدرسیده را با بودجهٔ شبکهٔ ۱۵ ثانیه بررسی می‌کند. فاصلهٔ هر استراتژی و قفل مشترک از اجرای هم‌زمان جلوگیری می‌کنند. خطا و زمان بررسی در کارت استراتژی نمایش داده می‌شود. با بسته شدن صفحه، خواب دستگاه یا قطع اتصال، پایش متوقف می‌شود؛ تب پس‌زمینه هم ممکن است کندتر اجرا شود. پایش دائمی به سروری با امکان اجرای worker.php نیاز دارد.

دامنهٔ مقصد `ashkufaraz.ir` است. مسیر ریشهٔ وب در حساب FTP جدید باید پیش از انتشار با یک فایل آزمایشی تأیید شود. انتشار کد، پایگاه داده و استراتژی‌های موجود روی هاست را بازنویسی نمی‌کند.

سرور FTPS با گواهی معتبر `vip200.tntcloudmgmtdns.com` است؛ این نام و `ftp.ashkufaraz.ir` در زمان انتقال به یک IP اشاره می‌کنند. اطلاعات ورود فقط در GitHub Actions Secrets نگهداری می‌شوند. گردش کار `Check hosting connection` ارتباط FTP و اتصال پوشهٔ مقصد به دامنه را با فایل موقت بررسی می‌کند.

حساب فعلی از ریشهٔ خانگی `/home/ashkufaraz` شروع می‌شود؛ مقصد انتشار داخل FTP برابر `/public_html` است. بنابراین `FTP_REMOTE_DIR=/public_html` و `FTP_ALLOW_ACCOUNT_ROOT=false` تنظیم شده‌اند. پیش از هر انتشار، فایل موقت برای تطبیق همین پوشه با ریشهٔ دامنه بررسی و سپس حذف می‌شود.

HTTPS دامنه در بررسی ۲۰۲۶/۱۱/۱۲ معتبر است و `REQUIRE_HTTPS=true` تنظیم شده است. پس از بازشدن پورت‌های Passive و موفقیت انتقال، انتشار خودکار با `FTP_DEPLOY_ENABLED=true` فعال شده است. Secrets فقط در GitHub نگهداری می‌شوند.

برای پایش مستقل از مرورگر در هاست جدید، [راهنمای Cron سی‌پنل](../docs/cpanel-cron-fa.md) را ببینید. انتشار `cron.php` به‌تنهایی Cron Job را ایجاد نمی‌کند؛ زمان‌بندی باید در سی‌پنل تنظیم شده باشد.

این پوشه بستهٔ انتشار امن را می‌سازد و از طریق **FTPS با بررسی گواهی TLS** ارسال می‌کند. رمز FTP یا رمز پنل نباید داخل کد، فایل workflow یا README نوشته شود.

## محدودیت InfinityFree رایگان

این سرویس برای اجرای worker دائمی پروژه مناسب نیست. اجرای Cron و پردازش‌های طولانی پس‌زمینه پشتیبانی نمی‌شود؛ بنابراین بررسی از صفحهٔ باز جایگزین پایش ۲۴ساعته نیست.

منبع: [راهنمای رسمی محدودیت اجرای برنامه‌ها در InfinityFree](https://forum.infinityfree.com/t/how-to-install-a-laravel-site-on-infinityfree/118578).

برای اجرای کامل، هاست یا سروری با امکان اجرای PHP CLI دائمی، ذخیره‌سازی پایدار و دسترسی به API والکس لازم است. worker باید روی همان داده‌ای کار کند که پنل استفاده می‌کند. worker محلی به‌طور خودکار با دیتابیس هاست همگام نمی‌شود.

## تنظیمات مخزن GitHub

در `Settings → Secrets and variables → Actions` این Secretها را تعریف کنید:

| Secret | مقدار |
| --- | --- |
| `FTP_HOST` | نام سرور FTP، بدون پروتکل |
| `FTP_USERNAME` | نام کاربری FTP |
| `FTP_PASSWORD` | رمز FTP |
| `PANEL_PASSWORD` | رمز مستقل پنل اینترنتی؛ حداقل ۱۶ نویسه |

و این Variableها:

| Variable | مقدار |
| --- | --- |
| `SITE_HOSTS` | دامنه‌های مجاز، جداشده با ویرگول؛ بدون https و مسیر |
| `PANEL_USERNAME` | نام ورود پنل؛ پیش‌فرض admin |
| `FTP_REMOTE_DIR` | مسیر دقیق ریشهٔ سایت در FTP؛ پیش‌فرض `/htdocs`؛ قبل از فعال‌سازی باید بررسی شود |
| `FTP_DEPLOY_ENABLED` | فقط وقتی آمادهٔ انتشار هستید `true` قرار دهید |

اگر این متغیر آخر تعریف نشده یا true نباشد، تست‌ها اجرا و مرحلهٔ انتشار رد می‌شود. با رمز نامعتبر یا تنظیمات ناقص، انتشار موفق نمی‌شود.

## روند انتشار

بعد از هر **push به شاخهٔ main**، workflow `Test and deploy hosting` اجرا می‌شود. ابتدا تست‌های PHP، رابط و بستهٔ انتشار بررسی می‌شوند؛ سپس در صورت فعال بودن تنظیم بالا، فایل‌ها ارسال می‌شوند. `workflow_dispatch` امکان اجرای دستی از صفحهٔ Actions را هم فراهم می‌کند. صرف ذخیرهٔ فایل روی کامپیوتر، بدون commit و push، چیزی به هاست ارسال نمی‌کند.

انتشارهای هم‌زمان در صف قرار می‌گیرند. هر فایل ابتدا با نام موقت ارسال و سپس تغییر نام داده می‌شود. فایل‌های نامرتبط روی هاست حذف نمی‌شوند؛ حذف یک فایل از Git به معنی حذف نسخهٔ قدیمی آن از هاست نیست و در صورت نیاز باید جداگانه بررسی شود.

## چیدمان و دسترسی

در مسیر مقصد، `public`، `src`، `config` و `data` ایجاد می‌شوند و ورودی اصلی به `public/` هدایت می‌شود. دسترسی مستقیم وب به src، config و data با `.htaccess` بسته است. این روش به وب‌سرور سازگار با تنظیمات Apache نیاز دارد؛ پیش از استفاده باید مسدودبودن واقعی این مسیرها تأیید شود.

پنل و API به رمز مستقل و HTTPS نیاز دارند. مرورگر پنجرهٔ استاندارد ورود را نمایش می‌دهد. رمز پنل در بسته به‌صورت هش PHP ذخیره می‌شود. آدرس میزبان نامعتبر رد می‌شود و پس از ده تلاش ناموفق از یک IP، ورود برای پنج دقیقه محدود می‌شود. این تنظیمات فقط در بستهٔ ساخته‌شده اعمال می‌شوند؛ اجرای محلی پروژه تغییر نمی‌کند.

فایل‌های SQLite، WAL/SHM، قفل، لاگ و دادهٔ شخصی از کامپیوتر منتقل نمی‌شوند. داده‌های موجود روی هاست حفظ می‌شوند؛ اولین انتشار با دیتابیس خالی شروع می‌شود. انتقال استراتژی‌های فعلی یا دیتابیس، عملیات جداگانه است. نسخهٔ کنونی بسته، worker دائمی را روی InfinityFree راه‌اندازی نمی‌کند.

HTTPS، نسخهٔ PHP، افزونه‌های curl و pdo_sqlite، مجوز نوشتن data و دسترسی خروجی به والکس باید روی هاست بررسی شوند. اگر دامنه یا ریشهٔ FTP اشتباه باشد، فایل‌ها نباید منتشر شوند.

## آزمایش محلی ابزار انتشار

```text
php tests/hosting.php
python tests/deployment.py
```

این تست‌ها از رمز نمونه و پوشهٔ موقت استفاده می‌کنند؛ به FTP واقعی متصل نمی‌شوند و اطلاعات اصلی برنامه را تغییر نمی‌دهند.
